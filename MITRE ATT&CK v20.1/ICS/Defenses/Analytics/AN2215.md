# AN2215 - Analytic 2215

[ICS](../../README.md) / [Analytics](README.md)

Real-time monitoring cross-correlates a field device's reported telemetry against an independent secondary measurement, identifying cases where the reported value diverges from the independent reading while the device's network-layer identity shows a MAC mismatch against its enrolled hardware address. Spoofed reporting messages are, by definition, designed to look protocol-valid. OT operational-fidelity gate: Alert only when the action is not attributable to an authorized operator/engineering source for the specific target and function, and it is either outside an approved change/maintenance window or lacks matching change-control context; where telemetry permits, require corroborating device, configuration, or process-state effect. Suppress activity that fully matches approved maintenance, commissioning, failover, recovery, or tested control procedures.

## Log sources and channels

- **operationaldb:ProcessHistory** — reported values show statistically improbable stability during a period when physical process is known to be actively changing · [DC0107 - Process History/Live Data](../Data%20Components/DC0107%20-%20Process%20History%20-%20Live%20Data.md)
- **NSM:Flow** — reporting message for device_ip originates from src_mac not matching enrolled hardware address for that Internet Protocol (IP) · [DC0078 - Network Traffic Flow](../Data%20Components/DC0078%20-%20Network%20Traffic%20Flow.md)
- **processsensor:RedundantComparison** — device-reported value for a tag diverges from independently measured value for same physical quantity by more than sensor tolerance threshold · [DC0108 - Device Alarm](../Data%20Components/DC0108%20-%20Device%20Alarm.md)

## Mutable elements

- **SensorToleranceThreshold** — Acceptable divergence between primary and independent secondary measurement of the same physical quantity.
- **ZeroVarianceWindow** — Time window over which reported values are checked for implausible stability.

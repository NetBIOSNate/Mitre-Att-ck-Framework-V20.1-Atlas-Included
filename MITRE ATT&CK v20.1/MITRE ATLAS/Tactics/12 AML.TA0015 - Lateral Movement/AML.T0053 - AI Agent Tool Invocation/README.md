# AML.T0053 - AI Agent Tool Invocation

[MITRE ATLAS](../../../README.md) / [AML.TA0015 - Lateral Movement](../README.md)

Adversaries may use their access to an AI agent to invoke tools the agent has access to. LLMs are often connected to other services or resources via tools to increase their capabilities. Tools may include integrations with other applications, access to public or private data sources, and the ability to execute code.

This may allow adversaries to execute API calls to integrated applications or services, providing the adversary with increased privileges on the system. Adversaries may take advantage of connected data sources to retrieve sensitive information. They may also use an LLM integrated with a command or script interpreter to execute arbitrary instructions.

AI agents may also invoke applications indirectly through operating-system mechanisms such as deep links, app-intent URIs, universal links, or redirect chains. This can cause an installed application to open or perform an application-specific action even when that application was not selected as a direct agent tool, potentially avoiding normal user-confirmation workflows.

An AI agent may exercise its own permissions or permissions delegated by a user on the adversary's behalf. When the agent treats an unauthorized request as sufficient authority to act, it may function as a privileged proxy, creating a confused-deputy condition. This authority can provide functional access to tools inaccessible to normal users. The adversary does not need to obtain the agent's credentials or impersonate the agent for this behavior to occur.

## Mitigations

- [AML.M0020 - Generative AI Guardrails](../../../Mitigations/AML.M0020%20-%20Generative%20AI%20Guardrails.md) — Validate proposed tool selections, arguments, targets, and destinations against the authorized task and applicable policies before execution. Block disallowed operations and inspect returned content before adding it to model context.
- [AML.M0021 - Generative AI Guidelines](../../../Mitigations/AML.M0021%20-%20Generative%20AI%20Guidelines.md) — Model guidelines can instruct the model to refuse a response to unsafe inputs.
- [AML.M0022 - Generative AI Model Alignment](../../../Mitigations/AML.M0022%20-%20Generative%20AI%20Model%20Alignment.md) — Model alignment can improve the parametric safety of a model by guiding it away from unsafe prompts and responses.
- [AML.M0024 - AI Telemetry Logging and Monitoring](../../../Mitigations/AML.M0024%20-%20AI%20Telemetry%20Logging%20and%20Monitoring.md) — Log AI agent tool invocations to detect malicious calls.
- [AML.M0026 - Manage AI Agent Service Access](../../../Mitigations/AML.M0026%20-%20Manage%20AI%20Agent%20Service%20Access.md) — Assign dedicated service identities with tool and resource permissions limited to approved workflows. Authorize workflow initiators and separate roles with materially different privileges to prevent requests from exercising unrelated agent capabilities.
- [AML.M0027 - Manage User-Delegated AI Agent Access](../../../Mitigations/AML.M0027%20-%20Manage%20User-Delegated%20AI%20Agent%20Access.md) — Limit delegated tool operations and resource access to the agent's tasks, bounded by the authorizing user's current permissions. Do not automatically grant all access available to the user.
- [AML.M0028 - Enforce Access Controls for AI Agent Tools](../../../Mitigations/AML.M0028%20-%20Enforce%20Access%20Controls%20for%20AI%20Agent%20Tools.md) — Authenticate callers and authorize each tool invocation against the requested operation, target resource, and delegated permissions. Enforce checks outside the model and limit backend identity privileges to required operations and resources.
- [AML.M0029 - Human In-the-Loop for AI Agent Actions](../../../Mitigations/AML.M0029%20-%20Human%20In-the-Loop%20for%20AI%20Agent%20Actions.md) — Requiring user confirmation of AI agent tool invocations can prevent the automatic execution of tools by an adversary.
- [AML.M0030 - Restrict AI Agent Tool Invocation on Untrusted Data](../../../Mitigations/AML.M0030%20-%20Restrict%20AI%20Agent%20Tool%20Invocation%20on%20Untrusted%20Data.md) — Restricting the automatic tool use when untrusted data is present can prevent adversaries from invoking tools via prompt injections.
- [AML.M0032 - Segmentation of AI Agent Components](../../../Mitigations/AML.M0032%20-%20Segmentation%20of%20AI%20Agent%20Components.md) — Segmentation can prevent adversaries from utilizing tools in an agentic workflow to perform unsafe actions that affect other components.
- [AML.M0033 - Input and Output Validation for AI Agent Components](../../../Mitigations/AML.M0033%20-%20Input%20and%20Output%20Validation%20for%20AI%20Agent%20Components.md) — Validation can prevent adversaries from utilizing tools in an agentic workflow to generate unsafe output.
- [AML.M0035 - AI Red Team](../../../Mitigations/AML.M0035%20-%20AI%20Red%20Team.md) — Attempt to select unauthorized tools, supply unsafe arguments, exceed user privileges, or chain tools into harmful actions. Correct permissions, argument validation, sandboxing, action controls, and approval requirements.
- [AML.M0038 - AI Agent Scope Drift Detection](../../../Mitigations/AML.M0038%20-%20AI%20Agent%20Scope%20Drift%20Detection.md) — Identify tool-use inconsistent with the assigned task as potential scope-drift indicator.

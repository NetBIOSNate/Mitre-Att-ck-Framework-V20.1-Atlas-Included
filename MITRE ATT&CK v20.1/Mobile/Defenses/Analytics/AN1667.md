# AN1667 - Analytic 1667

[Mobile](../../README.md) / [Analytics](README.md)

For Android, detect Dynamic Resolution by correlating analyst-visible device/network evidence and management state; use streaming or batched telemetry only where the documented collector is deployed. Correlate API Calls via Application Vetting / Instrumented Dynamic Analysis [Dynamic API/runtime trace: InetAddress.getByName() or DnsResolver called > $DGACandidateThreshold$ times with algorithmically-distinct hostnames in $DGAWindow$ — rapid programmatic resolution attempts]; Network Connection Creation via Android Enterprise Network Logging / Enterprise VPN [DevicePolicyManager.retrieveNetworkLogs(): DnsEvent / ConnectEvent; VPN flow metadata]; Network Traffic Flow via Android Enterprise Network Logging / Enterprise VPN [DevicePolicyManager.retrieveNetworkLogs(): DnsEvent / ConnectEvent; VPN flow metadata]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone.

[MITRE ATT&CK record](https://attack.mitre.org/detectionstrategies/DET0613#AN1667)

## Mutable elements

- **NXDOMAINThreshold** — Default 20 per device per app within window. Tightening: 10. Derive from per-app DNS baseline.
- **DGAWindow** — Default 60s.
- **DGASuccessWindow** — Default 30s between last NXDOMAIN and successful resolution.
- **AppBaselineDomains** — Per-app known CDN/update domains from 30-day baseline.
- **DGACandidateThreshold** — Default 10 distinct hostname queries within window.

# AN1838 - Analytic 1838

[Mobile](../../README.md) / [Analytics](README.md)

For Android, detect Compromise Client Software Binary from documented management, network, or vetting evidence; treat state queries as periodic observations rather than real-time events. Correlate File Metadata via Application Vetting / Forensic Acquisition [Dynamic filesystem trace or acquired app-container/filesystem artifacts: file hash changes for binary at $SystemBinaryPaths$ relative to known-good baseline — hash deviation confirms modification]; File Modification via Application Vetting / Forensic Acquisition [Dynamic filesystem trace or acquired app-container/filesystem artifacts: write() to path IN $SystemBinaryPaths$ by process NOT IN $TrustedUpdateSources$]; Process Creation via Application Vetting / Managed Device Telemetry [execve() of modified binary (hash != baseline) — execution of modified binary is the persistence activation]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone.

[MITRE ATT&CK record](https://attack.mitre.org/detectionstrategies/DET0712#AN1838)

## Mutable elements

- **SystemBinaryPaths** — /system/bin/, /system/xbin/, /system/vendor/bin/. Vary by OEM.
- **TrustedUpdateSources** — OTA update service, MDM agent. Derive from MDM platform documentation.
- **BinaryHashBaseline** — Known-good hash per binary per Android version. Update on each OS release.

# AN1774 - Analytic 1774

[Mobile](../../README.md) / [Analytics](README.md)

For Android, detect Calendar Entries by correlating analyst-visible device/network evidence and management state; use streaming or batched telemetry only where the documented collector is deployed. Correlate API Calls via Application Vetting / Instrumented Dynamic Analysis [Dynamic API/runtime trace: ContentResolver.query(CalendarContract) with query_count > $CalendarQueryThreshold$ by app NOT IN $ApprovedCalendarApps$]; Network Traffic Flow via Android Enterprise Network Logging / Enterprise VPN [DevicePolicyManager.retrieveNetworkLogs(): DnsEvent / ConnectEvent; VPN flow metadata]; Permissions Request via Android Enterprise DPC / Application Vetting [DevicePolicyManager.getPermissionGrantState(); PackageManager manifest/requested-permission review]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone.

[MITRE ATT&CK record](https://attack.mitre.org/detectionstrategies/DET0674#AN1774)

## Mutable elements

- **ApprovedCalendarApps** — Exchange, Google Calendar, enterprise calendar sync apps.
- **CalendarQueryThreshold** — Default 30 queries/2min. Tune per calendar sync app baseline.
- **CalendarUplinkThreshold** — Default 50KB — ~25 calendar events average ~2KB each.
- **CalendarSyncCDNList** — O365, Google Calendar API endpoints.
- **ExfilWindow** — Default 120s.

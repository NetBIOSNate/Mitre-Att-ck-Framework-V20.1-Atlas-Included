# AN1775 - Analytic 1775

[Mobile](../../README.md) / [Analytics](README.md)

For iOS, detect Calendar Entries by correlating analyst-visible device/network evidence and management state; use streaming or batched telemetry only where the documented collector is deployed. Correlate API Calls via Application Vetting / Instrumented Dynamic Analysis [Dynamic API/runtime trace: EKEventStore.fetchEvents() or enumerateEvents() with date_range > $CalendarDateRangeThreshold$ days by app NOT IN $ApprovedCalendarApps$]; Network Traffic Flow via Apple Network Extension / Enterprise VPN [NEFilterFlow / per-app VPN / secure-web-gateway flow metadata]; Permissions Request via Application Vetting [Code-signing entitlements and Info.plist privacy usage-description keys]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone.

[MITRE ATT&CK record](https://attack.mitre.org/detectionstrategies/DET0674#AN1775)

## Mutable elements

- **ApprovedCalendarApps** — com.microsoft.outlook, com.google.calendar.app, enterprise calendar bundles.
- **CalendarDateRangeThreshold** — Default 365 days — full-store fetch vs incremental sync.
- **CalendarUplinkThreshold** — Default 50KB.
- **CalendarSyncCDNList** — O365, Google Calendar API endpoints.
- **ExfilWindow** — Default 120s.

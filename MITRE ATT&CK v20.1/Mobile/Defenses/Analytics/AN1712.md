# AN1712 - Analytic 1712

[Mobile](../../README.md) / [Analytics](README.md)

For Android, detect File Deletion from documented management, network, or vetting evidence; treat state queries as periodic observations rather than real-time events. Correlate Application Permission via Android Enterprise DPC / Application Vetting [DevicePolicyManager.getPermissionGrantState(); PackageManager manifest/requested-permission review]; File Deletion via Application Vetting / Forensic Acquisition [Dynamic filesystem trace or acquired app-container/filesystem artifacts: App deletes, truncates, or removes files that were recently written by the same app (collected data, staged exfil artifacts, operation logs) within $PostExfilCleanupWindow$ of network upload event — post-exfil cleanup chain]; OS API Execution via Application Vetting / Instrumented Dynamic Analysis [Dynamic API/runtime trace: App invokes file management, storage-clear, or wipe operations in background state following network upload without user-initiated delete action]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone.

[MITRE ATT&CK record](https://attack.mitre.org/detectionstrategies/DET0638#AN1712)

- **mobile:DynamicAnalysis** — Dynamic API/runtime trace: App invokes file management, storage-clear, or wipe operations in background state following network upload without user-initiated delete action · [DC0021 - OS API Execution](../Data%20Components/DC0021%20-%20OS%20API%20Execution.md)

## Mutable elements

- **PostExfilCleanupWindow** — Default 300s after network upload event within which subsequent file deletions by the same app are causally linked to post-exfil cleanup. Tightening: 60s.
- **EvidenceFilePatterns** — Audio/video files in app private storage, SQLite databases, screenshot files, log files written by malware. Derive from expected malware artifact patterns.

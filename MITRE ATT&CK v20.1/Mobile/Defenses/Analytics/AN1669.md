# AN1669 - Analytic 1669

[Mobile](../../README.md) / [Analytics](README.md)

For Android, detect Drive-By Compromise by correlating analyst-visible device/network evidence and management state; use streaming or batched telemetry only where the documented collector is deployed. Correlate File Creation via Application Vetting / Forensic Acquisition [Dynamic filesystem trace or acquired app-container/filesystem artifacts: open() with O_CREAT for APK or binary file in /sdcard/ or /data/local/tmp/ by browser process within $DriveByWindow$ — payload drop confirms exploit code execution]; Network Traffic Content via Enterprise Secure Web Gateway / Proxy [DNS/HTTP(S) inspection or proxy transaction metadata where enterprise decryption/inspection is deployed]; Process Creation via Application Vetting / Managed Device Telemetry [execve()]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone.

[MITRE ATT&CK record](https://attack.mitre.org/detectionstrategies/DET0614#AN1669)

**Platforms**  [Android](../../Platforms/Android.md)

## Mutable elements

- **URLReputationThreshold** — Default score 50/100. Derive from threat intel feed vendor scoring.
- **DomainAgeDays** — Default 30 days. Newly registered domain + browser exploit = high-confidence.
- **KnownBrowserChildren** — Renderer, GPU process, browser service workers. Derive from browser process baseline.
- **DriveByWindow** — Default 30s between URL navigation and process spawn.

# AN1776 - Analytic 1776

[Mobile](../../README.md) / [Analytics](README.md)

For Android, detect Location Tracking by correlating analyst-visible device/network evidence and management state; use streaming or batched telemetry only where the documented collector is deployed. Correlate API Calls via Application Vetting / Instrumented Dynamic Analysis [Dynamic API/runtime trace: LocationManager.requestLocationUpdates() called with minTime < $LocationUpdateFreqThreshold$ by app NOT IN $LocationAllowList$]; Network Traffic Content via Enterprise Secure Web Gateway / Proxy [DNS/HTTP(S) inspection or proxy transaction metadata where enterprise decryption/inspection is deployed]; Permissions Request via Android Enterprise DPC / Application Vetting [DevicePolicyManager.getPermissionGrantState(); PackageManager manifest/requested-permission review]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone.

[MITRE ATT&CK record](https://attack.mitre.org/detectionstrategies/DET0675#AN1776)

## Mutable elements

- **LocationAllowList** — Navigation, delivery, enterprise fleet management apps. Derive from MDM catalog.
- **LocationUpdateFreqThreshold** — Default 60000ms (1 min) — below this = continuous surveillance vs occasional check-in.
- **LocationCDNList** — Google Maps, Apple Maps, Mapbox, enterprise fleet CDN endpoints.
- **ExfilWindow** — Default 300s.

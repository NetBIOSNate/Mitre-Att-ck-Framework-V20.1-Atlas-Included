# AN1670 - Analytic 1670

[Mobile](../../README.md) / [Analytics](README.md)

For iOS, detect Drive-By Compromise by correlating analyst-visible device/network evidence and management state; use streaming or batched telemetry only where the documented collector is deployed. Correlate Network Connection Creation via Apple Network Extension / Enterprise VPN [NEFilterFlow / per-app VPN / secure-web-gateway flow metadata]; Network Traffic Content via Enterprise Secure Web Gateway / Proxy [DNS/HTTP(S) inspection or proxy transaction metadata where enterprise decryption/inspection is deployed]; Process Creation via Application Vetting / Managed Device Telemetry [com.apple.WebKit or com.apple.WebContent process fault at level=fault within $DriveByWindow$ of navigation to flagged URL — kernel fault in WebKit subsystem is the exploit-execution signal]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone.

[MITRE ATT&CK record](https://attack.mitre.org/detectionstrategies/DET0614#AN1670)

**Platforms**  [iOS](../../Platforms/iOS.md)

## Mutable elements

- **URLReputationThreshold** — Default score 50/100.
- **DomainAgeDays** — Default 30 days.
- **DriveByWindow** — Default 30s.
- **SafariBrowsingBaseline** — Known CDN/content destinations from 30-day Safari baseline. Derive by measurement.
- **PostExploitWindow** — Default 60s between WebKit fault and post-exploit connection.

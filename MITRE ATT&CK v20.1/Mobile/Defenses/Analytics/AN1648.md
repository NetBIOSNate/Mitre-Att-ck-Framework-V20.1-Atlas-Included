# AN1648 - Analytic 1648

[Mobile](../../README.md) / [Analytics](README.md)

For Android, detect System Information Discovery by correlating analyst-visible device/network evidence and management state; use streaming or batched telemetry only where the documented collector is deployed. Correlate API Calls via Application Vetting / Instrumented Dynamic Analysis [Dynamic API/runtime trace: android.os.Build field reads > $SysInfoFieldThreshold$ distinct fields within $SysInfoWindow$ by app NOT IN $SysInfoAllowList$ at launch or in background]; Application State via Android Enterprise / EMM [Managed package inventory/status and package metadata]; Network Connection Creation via Android Enterprise Network Logging / Enterprise VPN [DevicePolicyManager.retrieveNetworkLogs(): DnsEvent / ConnectEvent; VPN flow metadata]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone.

[MITRE ATT&CK record](https://attack.mitre.org/detectionstrategies/DET0601#AN1648)

## Mutable elements

- **SysInfoFieldThreshold** — Default 5 distinct Build fields within window. Single-field reads are legitimate.
- **SysInfoWindow** — Default 30s at launch.
- **SysInfoAllowList** — MDM agent, crash reporter, analytics SDK (if pre-approved). Derive from MDM catalog.
- **AppCDNList** — Per-app CDN. Derive by measurement.
- **FollowOnWindow** — Default 120s.

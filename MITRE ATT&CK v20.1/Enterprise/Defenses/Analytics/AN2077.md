# AN2077 - Analytic 2077

[Enterprise](../../README.md) / [Analytics](README.md)

Detect successful SaaS authentication through an application-specific or legacy credential mechanism from a source/client not previously associated with that account, correlated with new session establishment or subsequent access inconsistent with ApprovedASPUsage.

[MITRE ATT&CK record](https://attack.mitre.org/detectionstrategies/DET0926#AN2077)

**Platforms**  [SaaS](../../Platforms/SaaS.md)

## Log sources and channels

- **saas:audit ** — Successful application-specific/legacy credential authentication where exposed  · [DC0002 - User Account Authentication](../Data%20Components/DC0002%20-%20User%20Account%20Authentication.md)
- **saas:audit** — ASP creation/modification event where supported  · [DC0010 - User Account Modification](../Data%20Components/DC0010%20-%20User%20Account%20Modification.md)
- **saas:session ** — New authenticated session associated with changed source/client context  · [DC0067 - Logon Session Creation](../Data%20Components/DC0067%20-%20Logon%20Session%20Creation.md)

## Mutable elements

- **ApprovedASPUsage** — Approved user/application/use-case relationships for ASP authentication—for example, which user or service is expected to use an ASP with which application. Derive from documented integration workflows and service ownership. Broadening permitted relationships reduces FP but increases FN for abused legitimate credentials; narrowing them increases detection sensitivity and FP.
